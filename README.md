# 발표 보스전

발표 자료와 발표문을 함께 보며 준비하고, 마이크로 연습하고, 질의응답 후 수정하는 한국어 웹앱입니다. HTML/CSS/JavaScript로 구현했으며 `public/` 폴더를 그대로 GitHub Pages에 배포할 수 있습니다.

## 실행

Node.js 22 이상에서 `Start.cmd`를 실행하거나 다음 명령을 사용합니다.

```sh
npm start
```

브라우저에서 **http://localhost:4173** 을 엽니다. 기본 실행에는 설치나 AI API 키가 필요하지 않습니다. PDF.js 배포 파일은 라이선스와 함께 포함되어 있습니다. HTML을 파일로 직접 여는 대신 HTTP 서버를 이용하세요.

## 사용 순서

1. `샘플로 먼저 연습하기` 또는 `새 발표 만들기`를 선택합니다.
2. 텍스트 PDF(20MB, 30페이지 이하)를 등록하거나 슬라이드 내용을 직접 입력합니다.
3. 페이지마다 발표문을 입력하거나 마이크로 녹음합니다. 음성 인식 결과는 수정할 수 있습니다.
4. `기본 점검하기` 또는 연결된 서버의 `AI 심화 분석`을 실행합니다.
5. 보스를 선택해 질문 3개와 각각의 꼬리질문에 답합니다.
6. 수정 미션을 확인하고 발표문을 수정한 뒤 재분석합니다. `성장 기록`에서 이전 발표문과 비교합니다.

## 기본 점검과 AI 분석의 차이

| 기능 | API 없이 | AI 서버 연결 시 |
| --- | --- | --- |
| PDF 추출·미리보기, 발표문, 녹음 | 지원 | 지원 |
| 발표 점검 | 빈 페이지, 표현 규칙, 단어 일치, 분량 | 자료·발표문 의미 비교, 누락·근거·불일치 |
| 질문 | 선택한 관점의 질문 템플릿 + 자료 제목 | 발표 내용에 기반한 질문 생성 |
| 꼬리질문 | 답변의 불확실성·수치 등 표현에 반응 | 실제 질문과 답변을 바탕으로 생성 |
| 수정 미션·재분석 비교 | 지원 | 지원 |

기본 점검은 의미나 사실의 진위를 검증하지 않습니다. 화면에서도 규칙 기반 점검으로 표시합니다. AI 판단 역시 사용자가 관련 자료와 함께 확인해야 합니다. 점검 항목 수가 줄었다고 발표 능력이 향상되었다고 단정하지 않습니다.

## 마이크

- HTTPS 또는 localhost에서 사용자 권한을 받아 녹음합니다.
- MediaRecorder로 실제 녹음·재생합니다. 녹음 중 페이지 이동을 막아 슬라이드별 녹음을 구분합니다.
- 브라우저 SpeechRecognition 지원 시 한국어 음성을 텍스트로 변환합니다. 해당 브라우저의 음성 서비스가 음성을 처리할 수 있으며 브라우저·네트워크에 따라 지원이 다릅니다.
- 받아쓰기가 지원되지 않거나 실패하면 녹음 재생 후 직접 입력할 수 있습니다. 음성 인식 실패를 분석 성공으로 표시하지 않습니다.
- 발음·억양 평가는 구현하지 않았습니다. 발표문 시간은 공백 제외 분당 300자에 따른 추정입니다.
- 페이지당 녹음은 10분으로 제한됩니다. 녹음 파일은 현재 탭에만 남으며 새로고침하면 사라집니다.

## 데이터

- 프로젝트, 슬라이드 추출 텍스트, 발표문, 최근 20회 분석 및 현재 보스전은 브라우저 localStorage에 저장됩니다. 브라우저 데이터 삭제 시 없어집니다.
- PDF 원본은 저장·업로드하지 않습니다. 새로고침 후 원본 미리보기를 보려면 같은 PDF를 다시 열어야 합니다. PDF 지문이 같은 경우 기존 발표문을 유지합니다.
- 백업 내보내기에는 프로젝트 데이터와 현재 보스전이 포함됩니다. 불러오기는 발표문과 분석 기록을 복원하며, 보스전은 새로 시작합니다.
- 새 PDF로 교체하기 전 확인을 요청합니다. 기존 분석 스냅샷은 유지합니다.
- AI 모드에서는 추출된 자료와 발표문, 질문·답변이 설정한 서버 및 AI 제공자에게 전송됩니다. 원본 녹음은 AI 서버로 전송하지 않습니다.
- 기본 점검은 브라우저 안에서 처리합니다. 화면 글꼴은 Google Fonts에서 로드하며 실패 시 시스템 글꼴을 사용합니다.

## AI 서버 설정 (선택)

`.env.example`을 `.env`로 복사한 뒤 서버 환경에서 설정합니다.

```dotenv
OPENAI_API_KEY=여기에_서버용_API_키
OPENAI_MODEL=계정에서_사용_가능한_Responses_Structured_Outputs_지원_모델
```

서버를 재시작하면 같은 서버에서 열린 화면은 자동으로 연결 여부를 확인합니다. 키와 모델이 둘 다 설정되어야 AI 버튼이 활성화됩니다. 연결 상태는 설정 존재 여부이며 실제 모델 접근·잔액까지 보장하지 않습니다. 실제 호출 실패는 화면에 표시됩니다. API 사용 요금은 별도입니다.

Responses API의 JSON Schema 출력으로 결과 형식을 제한하고, 서버에서 페이지 번호와 질문 수를 검증합니다. 타임아웃, 본문 크기 제한, 분당 요청 제한, 최대 동시 요청 제한을 적용했습니다. API 키는 프런트엔드로 보내지 않습니다.

공식 문서: https://developers.openai.com/api/docs/guides/structured-outputs

## GitHub Pages 배포

저장소 Settings → Pages → Source를 **GitHub Actions**로 선택합니다. `main` 브랜치에 push하면 포함된 workflow가 `public/`만 배포합니다. 서버 코드와 `.env`는 Pages 배포에 포함되지 않습니다.

Pages에서는 기본 기능을 바로 사용할 수 있습니다. AI 기능을 쓰려면 `server.mjs`를 별도 HTTPS Node 서버에 호스팅하고 아래 변수를 설정합니다.

```dotenv
HOST=0.0.0.0
ALLOWED_ORIGIN=https://사용자명.github.io
APP_ACCESS_TOKEN=직접_생성한_충분히_긴_비밀_접속_토큰
```

앱의 `연결 설정`에 서버 주소와 **접속 토큰**을 입력합니다. AI 제공자의 API 키를 입력하면 안 됩니다. 접속 토큰은 sessionStorage에만 저장합니다. 외부 origin을 설정하면 접속 토큰 없이 API를 열 수 없도록 했습니다. 개인 시연을 위한 구성으로, 불특정 다수 서비스 운영 전에는 사용자별 인증·요금 한도를 추가해야 합니다. CORS의 origin은 경로를 포함하지 않습니다.

## 검증

```sh
npm test
```

규칙 기반 점검과 꼬리질문 분기 테스트입니다. 브라우저 테스트는 Playwright와 Edge가 설치된 환경에서 서버 실행 후 다음과 같이 수행합니다.

```sh
node tests/browser.cjs
```

테스트용 `artifacts/test.pdf`(첫 페이지에 `CAPSTONE DEMO` 텍스트)를 준비해야 합니다. 필요하면 `PLAYWRIGHT_MODULE` 환경변수로 기존 Playwright 모듈 위치를 지정합니다. 브라우저 테스트 산출물은 `artifacts/`에만 저장하며 Git에 포함하지 않습니다.

실제 AI 호출은 유효한 키·모델을 설정한 후 별도 확인해야 합니다. 마이크 하드웨어와 한국어 받아쓰기 품질은 실제 기기에서 확인해야 합니다.

## 파일

- `public/index.html`, `style.css`, `app.js`: 화면과 사용자 흐름
- `public/engine.js`: 명시적인 기본 점검·질문 규칙
- `public/vendor/`: PDF.js 6.4.299, CMaps·폰트·WASM 및 라이선스
- `server.mjs`: 정적 서버와 AI API 중계
- `.github/workflows/pages.yml`: GitHub Pages 배포
- `tests/`: 규칙·브라우저 검증

PDF.js는 Apache-2.0이며 상세 라이선스는 `public/vendor/PDFJS-LICENSE.txt` 및 각 리소스 폴더에 포함됩니다.
